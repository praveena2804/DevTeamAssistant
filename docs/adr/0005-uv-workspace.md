# ADR-0005: uv workspace monorepo with one package per agent

- **Status:** Proposed. The implementation proceeds on the recommended default of D-26 (a). **Owner approval is pending.**
- **Date:** 2026-11-19
- **Related:** roadmap §7, §8; decisions D-26 (supersedes D-13)

## Decision

The repository is a uv workspace. Members:

- `packages/core`
- `packages/state`
- `packages/harness`
- `packages/orchestration`
- `packages/services`
- `apps/api`
- `apps/worker`
- exactly ten `agents/<name>` packages

Dependency direction (roadmap §7.1) is enforced by declared workspace dependencies plus import-linter contracts. The contracts active in Part A:

- `core` depends on no internal package;
- `state` depends only on `core`.

## Alternatives

- **(b) A single package with modules.** Simpler, but isolation would rely on convention instead of package boundaries.

## Consequences

- One lockfile: `uv.lock`, generated by `uv lock`, with `uv sync --locked` in CI.
- The decision is reversible before Part C adds the agent packages. After that, reversal is costly.
